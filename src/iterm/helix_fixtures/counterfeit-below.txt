   896  1. **A window title.** Helix sets none. Run in a pty for four seconds it wrote zero OSC 0, 1                    
   897     or 2 sequences, and its editor configuration has no title key — not in the 25.07.1                           
   898     binary's key list, not in the upstream `master` documentation. It is an open upstream                        
   899     request (`helix-editor/helix#2436`; `#2887` asks the same thing and was closed as its                        
   900     duplicate).                                                                                                  
   901  2. **iTerm2's own variables.** `commandLine` read `hx /Users/…/main.py`, and                                    
   902     `terminalWindowName` read `hx '/Users/…/main.py'` — the shell's pre-exec title, not                          
   903     Helix's. **Both are the launch arguments and stay them**: `hx .`, `:open`, the file                          
   904     picker, `gf` and a buffer switch all change what is open and change neither. A row built                     
   905     on them is right until the first file Helix opens by itself and confidently wrong for the                    
   906     rest of the session — §2.7's failure, with no staleness rule to catch it.                                    
   907  3. **An open file descriptor.** `lsof` on the Helix process showed one regular file,                            
   908     `~/.cache/helix/helix.log`. Helix reads a file and closes it.

   910     register an `oko-hook` equivalent with.

   912  What remains is the screen. A `GetBufferRequest` on that pane returned its 44 rows, and row 42                  
   913  read ` NOR   dev/labs/claude-certified-architect/main.py … 1 sel  10:1`.                                        
   914                                                                                                                  
   915  **Why this does not reopen §2.7.** §2.7 rejected reading the screen for *status*, on two                        
   916  grounds, and neither reaches this. There a structured source existed — hooks — and the screen                   
   917  would have been a worse copy of it; here nothing structured exists at all. And there the                        
   918  value read was the product's call to action: a wrong `waiting` sends a human to the wrong tab                   
   919  and is trusted because it is what the dashboard is for. A file name is context. **§2.7's                        
   920  principle is the one this design is built to keep rather than argue around**: the failure                       
   921  mode must be a value that stops updating, not one that lies. So a row gets a file only from a                   
   922  line matching Helix's status-line shape in full. Anything else — a customised status line, an                   
   923  overlay covering it, a screen mid-redraw — yields no new value, and a row that has never                        
   924  matched reads plain `hx`, exactly as it does today.
